# Freelance Milestone Escrow (POC)

A minimal, single-milestone escrow between a **client** and a **freelancer**, built as a
Web3 proof of concept: a Solidity contract plus a React frontend that connects via
**Rabby Wallet** (or any EIP-1193 wallet).

> ⚠️ Proof of concept only. Not audited. Do not deploy to mainnet or use with real funds.

## How it works

1. The client deploys the contract, naming the freelancer's address in the constructor.
2. The client calls `depositFunds()` to fund the milestone (`AWAITING_PAYMENT → FUNDED`).
3. Either:
   - The client calls `releasePayment()` once the work is approved, sending the full
     balance to the freelancer (`FUNDED → COMPLETED`), or
   - The freelancer calls `refundClient()` as a voluntary escape hatch, returning the
     full balance to the client (`FUNDED → REFUNDED`).

State transitions, roles, and transfers are all enforced on-chain; the frontend only
reflects contract state, it doesn't gate anything itself.

## Repo layout

```
contracts/FreelanceMilestoneEscrow.sol   Solidity contract (pragma ^0.8.20)
scripts/compile.js                       Compiles the contract with solc, writes artifacts/
scripts/deploy.js                        Deploys the compiled contract via ethers v6
artifacts/FreelanceMilestoneEscrow.json  ABI + bytecode (generated by `npm run compile`, gitignored)
frontend/                                Vite + React + ethers v6 dApp
```

## Phase 1 — Smart contract

### Design

- **Roles**: `client` (deployer) and `freelancer` (constructor argument), both `immutable`.
- **State machine**: `enum EscrowState { AWAITING_PAYMENT, FUNDED, COMPLETED, REFUNDED }`.
- **Security**: Checks-Effects-Interactions throughout (state is finalized *before* any
  external call), raw `call{value: ...}("")` for transfers (no `.transfer()`), and custom
  errors (`Unauthorized`, `InvalidState`, `ZeroAddress`, `ZeroDeposit`, `TransferFailed`)
  instead of `require` strings for cheaper reverts.

### Compile

```bash
npm install
npm run compile
```

This runs `scripts/compile.js` (uses the `solc` npm package directly — no external
compiler download required) and writes the ABI + bytecode to
`artifacts/FreelanceMilestoneEscrow.json`.

### Deploy

You need a JSON-RPC endpoint to deploy to — a local dev chain (e.g. `anvil` from
[Foundry](https://getfoundry.sh), or `npx ganache`) or a testnet (Sepolia, etc. via
Infura/Alchemy).

```bash
cp .env.example .env
# edit .env: RPC_URL, PRIVATE_KEY (client/deployer), FREELANCER_ADDRESS
npm run deploy
```

The script prints the deployed address — copy it into `frontend/.env` as
`VITE_CONTRACT_ADDRESS`.

## Phase 2 — Frontend

```bash
cd frontend
npm install
cp .env.example .env   # set VITE_CONTRACT_ADDRESS to your deployed address
npm run dev
```

Open the printed local URL with **Rabby Wallet** installed, connect, and:

- If your connected wallet is the **client**: deposit funds while `AWAITING_PAYMENT`,
  then approve/release once `FUNDED`.
- If your connected wallet is the **freelancer**: you can refund the client while
  `FUNDED` (the escape hatch).
- Anyone else sees the live status badge and balance, but no action buttons.

The frontend polls contract state after each transaction and also listens for
`FundsDeposited` / `PaymentReleased` / `ClientRefunded` events, so the UI updates live
without a page refresh — useful when testing with two wallets in two browser profiles.

### Notes on wallet connection

The connect flow calls the generic EIP-1193 `eth_requestAccounts` method and does **not**
check `window.ethereum.isMetaMask`, so it works correctly with Rabby Wallet (and other
injected wallets) rather than assuming MetaMask.

## Regenerating the frontend ABI

`frontend/src/abi.js` embeds the ABI produced by `scripts/compile.js`. If you change the
contract, recompile and update that file's `ESCROW_ABI` export to match
`artifacts/FreelanceMilestoneEscrow.json`.

## Diagrams

`DIAGRAMS.md` has Mermaid diagrams (rendered natively by GitHub): an architecture overview,
sequence diagrams for connect, `depositFunds()`, `releasePayment()` and `refundClient()`
(User/Wallet, Frontend, Ethers.js/Vite, contract), and the state machine with every
custom-error revert and a transition table.

## Interactive simulator (no wallet needed)

`docs/simulator.html` is a single-file, dependency-free replica of the escrow's state machine.
Open it directly in a browser (double-click, or `open docs/simulator.html`). Choose a role
(client / freelancer / stranger), call `depositFunds`, `releasePayment` or `refundClient`, and see
each call succeed or revert with the same custom errors as the contract. Toggles simulate a
recipient that rejects ETH or tries to re-enter, and you can force-send ETH via `selfdestruct`.
Log entries are tagged with the matching test ID from `test_plan.md` (e.g. `U-03`, `S-01`).
It mirrors the Solidity logic in JavaScript for learning and demos; the Hardhat tests remain the
source of truth.

## Testing

```bash
npm install
npm test                 # Hardhat: 31 contract tests (U-01..U-16, I-01..I-06, S-01..S-06)
npm run test:coverage    # optional coverage report
cd frontend && npm install && npm test   # Vitest: hook tests (I-07, I-08)
```

Hardhat is configured (`hardhat.config.cjs`) to compile with the pinned `solc` npm package, so no
compiler download is needed. Hardhat output goes to `hh-artifacts/`, leaving `artifacts/` to
`scripts/compile.js`. Mock contracts used only by tests live in `contracts/mocks/`.
